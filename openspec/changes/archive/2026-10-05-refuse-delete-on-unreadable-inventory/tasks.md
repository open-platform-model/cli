# Tasks: refuse-delete-on-unreadable-inventory

Three sections per design.md. Section 1 makes discovery return the entries it could not read, with every caller taking the new result and behaving as today; section 2 makes instance delete keep the `ModuleInstance` for them; section 3 makes the read-only commands warn and count them as not ready, and runs the cluster suites. Each section writes its failing tests first, with a fake dynamic client whose GET reactor returns `apierrors.NewForbidden`. Unit gates are `task fmt`, `task lint` and `task test:unit` (`task test` and `task check` chain the cluster suites); cluster suites run only under `flock <kind-opm-dev lock> <command>` (the agent prompt gives the lock path) against `kind-opm-dev`. Sections 2 and 3 change user-visible outcomes; their commit bodies carry the wording from proposal.md § Behaviour change for users (no body line may start with `word(`), but only the PR title reaches CHANGELOG.md, so section 4 hands the changelog line to the PR stage. Section 5 archives the change after the supervisor's review.

Coordination: cli PR #307 (another session, `feat/install-operator-from-module`) moves `executeInstanceDelete`'s body into `workflowapply.DeleteRecorded`/`DeleteRequest` and adds a second delete caller in `internal/operator/uninstall.go` (discovery, then `DeleteRecorded`). Whichever merges second rebases and keeps both sides' edits. If #307 merges first: add `Unreadable []kubernetes.UnreadableResource` to `workflowapply.DeleteRequest`, pass it into `DeleteOptions`, and have operator uninstall pass the unreadable slice from discovery, with a unit test. If this change merges first: the PR stage comments on #307 naming the uninstall caller so its rebase does not discard the slice as `_`.
