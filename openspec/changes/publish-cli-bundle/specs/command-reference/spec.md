## REMOVED Requirements

### Requirement: The command reference is generated from the command tree
**Reason**: `internal/cmdref` and `hack/cmdref` are deleted; docs-kit's `cobra` extractor renders the reference inside the cli's docs bundle from the dump `hack/docskit-dump` prints (docs-kit C19).
**Migration**: `task docs:bundle` replaces `task docs:reference`; the inputs (`Use`, `Short`, `Long`, `Example`, `Aliases`, flags) are unchanged.

### Requirement: Every entry has the same parts in the same order
**Reason**: The entry shape is docs-kit's (C19 D4), ported from cmdref with a recorded parity run.
**Migration**: None for authors; a rendering fix is a docs-kit change that reaches the cli at its next `.opm-docs-version` bump.

### Requirement: Generated pages follow the site page dialect
**Reason**: docs-kit lints every bundle in bundle mode before it publishes and again when the site pulls it (C11).
**Migration**: None.

### Requirement: Output is deterministic and machine-independent
**Reason**: Restated for the dump program in the `docs-bundle` capability; docs-kit's `check` runs the dump twice (C14) and `cobradump` writes the home directory as `~`.
**Migration**: None.

### Requirement: Generated text sits between marker comments
**Reason**: Nothing generated is committed, so there is no authored text to keep around a generated block.
**Migration**: Text that belongs beside the reference goes on an authored page outside `reference/cli/`.

### Requirement: A stale reference fails the check locally and in CI
**Reason**: Nothing generated is committed, so nothing can be stale.
**Migration**: `task docs:bundle:check` and the `Docs / check` job replace `task docs:reference:check` and the "Command Reference (current)" jobs.

## ADDED Requirements

### Requirement: The command reference is generated into the docs bundle

The CLI reference SHALL be generated by docs-kit's `cobra` extractor from the dump of the tree `internal/cmd.NewRootCmd` builds when the cli's docs bundle is built, at `reference/cli/` with the URLs it has today: the section page `/docs/reference/cli/` (title `CLI Reference`, weight 2, the global flags) and one page `/docs/reference/cli/opm-<command>/` per visible top-level command, anchors in kebab case (`#opm-module-apply`). Hidden and deprecated commands and flags and the `help` command SHALL be left out, and cobra's `completion` command SHALL be listed.

#### Scenario: A new subcommand appears in the reference

- **WHEN** a developer adds a visible subcommand `opm module foo`
- **THEN** the next bundle's `reference/cli/opm-module.md` holds an entry `## opm module foo`, and `opm module`'s entry lists it

#### Scenario: A hidden command stays out

- **WHEN** a command is hidden
- **THEN** no page of the bundle holds an entry for it

### Requirement: No generated reference page is committed

The repository SHALL NOT commit pages under `docs/site/reference/cli/` and SHALL carry no generator of its own for them; `.github/workflows/ci.yml` and `pr.yml` SHALL have no command-reference job. A committed page at a path the extractor writes SHALL fail the bundle build.

#### Scenario: A stray generated page is refused

- **WHEN** a contributor commits `docs/site/reference/cli/opm-module.md`
- **THEN** `task docs:bundle:check` fails, naming the colliding page
