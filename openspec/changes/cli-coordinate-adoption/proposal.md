# Proposal — cli-coordinate-adoption

## Why

The CLI is the last unretargeted Go consumer of the retired core v1 line. It pins `github.com/open-platform-model/library v1.0.0-alpha.9`; the library has since crossed to core v2 (alpha.12) and landed the 0010/0011 library slices (alpha.13): subscriptions are a required scalar `version` (`#SubscriptionFilter` and `synth.FilterSpec` no longer exist), materialize pulls exactly the named build and verifies artifact identity (`oerrors.IdentityError`), and unresolved demands fail `Compile` (`*oerrors.UnresolvedDemandsError`). Until the CLI crosses, every remaining 0011 CLI slice (`cli-publish-pipeline` → `cli-catalog-gates` → the publish cutovers → the republishes) builds on a retired schema line.

Under core v2 the identity reshape also dissolves the CLI's address arithmetic: `metadata.modulePath` is now the complete registry address (`@vN` suffix, snake-case leaf, `fqn == modulePath`), so `CanonicalModuleRef`'s composition (`modulePath + "/" + snakeLeaf + "@v" + MAJOR(version)`) would produce garbage like `opmodel.dev/modules/podinfo@v1/podinfo@v0` — the composition is deleted, not adapted. The library additionally now verifies declared identity against the fetched coordinate at every registry acquire, which is what actually kills the silent-downgrade defect (a published artifact with stale `metadata.version` resolving to an older real build, green forever); the CLI's `spec.module` write remains the *declared* coordinate, verified downstream at handoff and at the operator's acquire — a recorded reinterpretation of 0010 02-design's "write the coordinate actually fetched", which is unachievable on the CLI's write paths (`module apply` fetches nothing by design; `instance apply` loads through the file loader).

This change is 0010's `cli-coordinate-adoption` slice (see `enhancements/0010/plan.yaml`). Its decisions: D19, D42, D47, D49. Coordinated with the operator track: `operator-library-retarget` ships the v2 Platform CRD and `examples-fleet-core-v2` republishes the `opmodel.dev/modules/test/*` fixtures (podinfo at `v0.1.4`, `hello-web` renamed `hello_web`) in the next operator release (expected `v1.0.0-alpha.9`) — this change writes its pins for that state and gates the affected tests until the release exists.

## What Changes

- **`go.mod`: library `v1.0.0-alpha.9` → `v1.0.0-alpha.13`.** The only production compile break is `synth.FilterSpec` in `internal/platform/spec.go`; every kernel method the CLI calls is signature-identical.
- **Platform surface moves to the scalar-subscription shape** (`{enable?, version!}`, subscription keys carry the mandatory `@vN`):
  - `internal/platform/spec.go`: `wireFilter` deleted; `wireSubscription` gains `Version`; `toInput`/`wireFromInput` become straight copies.
  - `internal/config/schema/platform.cue`: `#SubscriptionFilter` deleted, `version!` required, registry keys constrained to major-suffixed module paths.
  - `internal/config/templates.go` `DefaultPlatformTemplate`: the retired `opmodel.dev/catalogs/kubernetes` subscription is dropped (D47 — absorbed into `catalog_opm`); the remaining subscription becomes `"opmodel.dev/catalogs/opm@v2": {version: "2.0.0-alpha.3"}`. The pin is load-bearing and hand-bumped; its peers are `hack/platform.cue` (same commit, mirror contract) and the operator's e2e Platform sample (recorded three-way alignment).
  - **CR paths split by direction**: `DecodeCRSpec` *permanently* tolerates legacy CRs — a stray `filter` is ignored, a missing `version` passes through to the library's `ErrSubscriptionMissingVersion` with a hint naming legacy filter-shaped CRs (stored CRs keep `filter` in etcd until their next spec write, so tolerance is not transitional). `EnsureClusterPlatform` *transitionally* refuses to write a cluster Platform while the vendored CRD lacks a `version` property (the API server would silently prune it), with an error naming the operator dependency; the refusal lifts at the operator re-vendor.
- **The fixture fleet crosses to core v2** — all 17 `core@v1` carriers: `cue.mod` pins to core `v2.0.0-alpha.4` + `catalogs/opm@v2` `v2.0.0-alpha.3`; imports to `core@v2` and the D49 versioned catalog packages (`…/{blueprints,resources,traits}/v1beta1` — all members verified present in the consolidated catalog); module metadata reauthored to the v2 identity shape (snake `name` equal to the path leaf, full `@vN` `modulePath`). `tests/integration/module-apply/testdata` is the in-repo model.
- **Address composition deleted** (`pkg/module/module.go`): `CanonicalModuleRef` keeps its name and callers but its body becomes a verbatim read — `(m.ModulePath, ensureVPrefix(m.Version))`. `majorVersionTag`, the snake-leaf fallback, and the `NameSnakeCase`/`DefaultNamespace` struct fields are deleted. `ensureVPrefix` survives: `metadata.version` is bare SemVer by `#VersionType` while `spec.module.version` and the registry tag are `v`-prefixed (the operator's `module.NewVersion` parse makes the prefix load-bearing). The unrelated private `ensureVPrefix` in `internal/inventory/gates.go` (CLI/operator build-version normalization) is untouched.
- **D19 warning**: the render path warns when the effective module context carries a local-path `replaceWith` in `cue.mod/local-module.cue` — "demanded keys may not correspond to published bytes". Instance-file renders reuse the already-computed `SourceLocal` predicate; module-directory renders gain the same check against the module root. (Refinement of D19's literal file-presence trigger, matching the repo's existing `HasLocalModuleReplacement` semantics and the source-local annotation's definition.)
- **New-error surfacing, minimal**: `cmdutil.PrintValidationError` gains one typed branch rendering `*oerrors.UnresolvedDemandsError` (component, contract key, kind, alternatives — instead of a flat error blob); `handoff/verify.go`'s acquire-failure message stops attributing every failure to "module not published" and names identity mismatches distinctly.
- **Cross-repo digest pin**: a unit test pins `sourceDigest`'s golden output with a comment naming the operator's `ModuleSourceDigest` as the byte-identical peer (the operator adds the mirror test in its retarget) — the invariant nothing previously checked.
- **Registry-pulled tests re-pin and stay gated until the operator release**: `render-parity`, the e2e handoff suite, and `examples/` move to podinfo `v0.1.4` (the `examples-fleet-core-v2` republish version); `examples/` goes podinfo-only (`hello-web`'s hyphenated name cannot exist on the v2 line; the renamed `hello_web` can be re-added later). Neither pulling test runs in PR CI; both keep their existing skip gates until the release ships the v2 artifacts.
- **Riders**: delete the dead `testing/test/` scaffold output; fix `version.CUESDKVersion` (`v0.15.0` → `v0.17.1`); update `vet_test.go`'s comments/skip text to the v2 line (its `debugValues` assertion survives — v2 keeps `debugValues: _`).
- **Verification-pass riders** (folded in after `/opsx:verify`): the delta specs are titled to the exact main-spec requirement headings so the sync is a name-matched replace (the transitional Cluster Platform Write Guard requirement is dropped from the delta — its code was added and removed within this change, and `design.md` plus the 0010 history are its record); a `test-fixture-lineage` delta moves the mandated fixture line to `core@v2`; the three pre-kernel loader specs (`module-receiver-methods`, `module-cue-evaluation`, `module-metadata-extraction`) are retired outright — they normatively describe `module.Load`, deleted at the 0006 kernel adoption, and this change removed the last live field they cite (`DefaultNamespace`); stale schema-line mentions in test comments and `docs/` examples move to the current line.
- **Deliberately NOT changed**: `internal/templates/*` (the `opm mod init` scaffolds, two schema lines stale) — owned by 0011's `cli-authoring-commands` (D12/D16 make `mod init` that slice's concern); broader typed routing for library errors; `DefaultRegistry`'s `testing.opmodel.dev` mapping (0011 `registry-cleanup`'s relocation decides it).

### Modified Capabilities

- `platform-resolution`: the platform projection is `{enable?, version!}` with major-suffixed keys; CR reads tolerate legacy filter CRs; CR writes are refused until the vendored CRD carries `version`.
- `config-commands`: the seeded `platform.cue` subscribes to `opmodel.dev/catalogs/opm@v2` only, with an explicit pinned `version`.
- `instance-building`: the builder loads `#ModuleInstance` from `opmodel.dev/core@v2`.
- `instance-inventory`: `spec.module.{path,version}` are sourced verbatim from v2 metadata (`modulePath` as-is; `version` v-prefixed), no composition.
- `kernel-render`: renders under a local-path module replacement warn that demanded keys may not correspond to published bytes (D19).

## Impact

- **SemVer: breaking** (`feat!`): the platform file format changes (`filter` → `version`, keys gain `@vN`), the seeded template changes, and renders that previously succeeded with warnings can now fail (library-side unresolved-demand semantics). Affected commands: `opm config init`, every render-bearing command (`module apply/build`, `instance apply/build/diff/vet`), `instance apply` thin-edit, `instance handoff`.
- **Packages touched**: `internal/platform`, `internal/config` (+ embedded schema + templates), `internal/workflow/{render,apply,handoff}`, `internal/cmdutil`, `pkg/module`, `internal/version`, CUE fixtures under `tests/`, `examples/`, `hack/`.
- **Blocked-on-release tail** (final task group, keyed on operator `v1.0.0-alpha.9`): `task operator:sync` + `PinnedOperatorVersion` bump (`v1.0.0-alpha.4` → the release), lift the CR-write refusal, move `hack/kind-platform.yaml`, un-gate the two pulling tests. Everything before it lands and is green now.
- **Complexity justification (Principle VII)**: no new flags, no new commands; one new typed-error branch and one warning, both replacing worse behavior (flat blobs, silent local-render false confidence).
